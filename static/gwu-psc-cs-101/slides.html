# Introduction

Five American states elect their governors in odd-numbered years, away from
federal elections. We ask whether this *timing* changes **who shows up to vote**.

Political scientists have long argued that off-cycle elections lower turnout and
hand more influence to organized groups [@anzia2011election; @anzia2014timing].
When citizens are unhappy with their government they can exit or they can use
their voice [@hirschman1970exit], and voting is the most common form of voice.^[All
data in this paper are simulated for teaching purposes.]

            
  • YAML header between --- lines: title, author, output settings.
  • R chunks in ```{r} fences; knitr runs them.
  • Everything else is Markdown, with [@citations].

git init Start tracking a folder
                Start

              
              
  • Turns the current folder into a Git repository by creating a hidden .git/ folder; the history will live there.
  • Nothing is saved yet. Run it once per project.
  • Files matching .gitignore (here build/, PDFs, caches) are never tracked: they can be regenerated.

              
From the demo

              
$ git init -b main
Initialized empty Git repository in ~/cs101-demo/alice/turnout-paper/.git/

            

            

              
git clone Copy a project, with its whole history
                Start

              
              
  • Downloads every file and every past version, and remembers where it came from (origin).
  • This is how a coauthor joins: no emailing zip files.

              
From the demo

              
$ git clone https://github.com/alice/turnout-paper.git
Cloning into 'turnout-paper'...
done.

            

            

              
git config Say who you are
                Start

              
              
  • Every commit is stamped with a name and email, so the history shows who changed what.
  • --global sets it for all your projects; without it, just this one.

              
From the demo

              
$ git config user.name "Bob"
$ git config user.email "bob@example.com"

            

            

              
git status What's going on right now?
                Record

              
              
  • Lists what changed since the last commit, and what is staged for the next one.
  • When in doubt, run git status: it usually tells you the next command too.

git add Pick what goes into the next snapshot
                Record

              
              
  • Moves changes to the staging area: a draft of the next commit.
  • git add . stages everything; git add paper.rmd just one file.

              
From the demo

              
$ git add .
$ git status
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
	new file:   .gitignore
	new file:   analysis/clean.R
…

            

            

              
git commit Save a snapshot
                Record

              
              
  • Records the staged changes as a new version, with a message saying why.
  • Each commit gets an ID like 7c6b9b2; you can always go back to it.
  • git commit -am "…" stages and commits changed files in one go.

              
From the demo

              
$ git commit -am "Sharpen the title"
[main 20367f1] Sharpen the title
 1 file changed, 1 insertion(+), 1 deletion(-)

git restore Throw away edits you haven't committed
                Record

              
              
  • Puts a file back the way it was in the last commit.
  • Careful: uncommitted changes are gone for good. Committed work is always safe.

              
From the demo

              
$ echo "% scratch" >> notes.txt
$ git restore notes.txt

            

            

              
git push Upload your commits
                Share

              
              
  • Sends your new commits to GitHub so coauthors can get them.
  • Rejected if someone pushed first: git pull, then push again.
  • The very first time: git remote add origin <url> (or gh repo create).

              
From the demo

              
$ git push -u origin main
To https://github.com/alice/turnout-paper.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
$ git push
To https://github.com/alice/turnout-paper.git
 ! [rejected]        main -> main (fetch first)
…

            

            

              
git pull Get your coauthors' commits
                Share

              
              
  • Downloads new commits and merges them into yours.
  • Different parts changed: merged automatically. Same lines changed: a conflict you resolve by hand, then git add + git commit.

git switch Work on a separate line of history
                Branch

              
              
  • git switch -c name starts a branch: an experiment that doesn't touch main.
  • git switch main goes back; your folder changes to match.
  • The Git answer to PaperFinalCopy2.docx.

              
From the demo

              
$ git switch -c numbered-citations
Switched to a new branch 'numbered-citations'
$ git switch main
Switched to branch 'main'
Your branch is up to date with 'origin/main'.

            

            

              
git merge Combine a branch into this one
                Branch

              
              
  • Brings another branch's commits into the current one.
  • If main hasn't moved, Git just moves it forward (fast-forward); otherwise it makes a merge commit.
  • git pull is git fetch + git merge.

              
From the demo

              
$ git merge numbered-citations
Updating aee74f0..e3c2e8d
Fast-forward
 paper.rmd | 1 +
 1 file changed, 1 insertion(+)
